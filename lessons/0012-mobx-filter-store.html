Lesson 0012 · MobX sub-lesson (08b)

Same page — state in a store

Lesson 0009 lifted filter state to the page parent and derived visible during render. That is the canonical React answer. At work, shared filter/sort state often lives in an SDK MobX store with a computed filtered list. This lesson rebuilds /rides with the same UI and behaviour — different owner for state.

Mission tie-in: curriculum 08b (MobX twin). Requires lesson 0009 solid first. Pair with lesson 0011: /rides-lift = React lift, /rides = MobX.

Two answers, one question

Lift (08a) /rides-lift MobX (08b) /rides
Filter state lives page.tsx useState Store fields (freeCancel, chips, …)
Visible list const visible = vehicles.filter… get visibleVehicles() computed
Sidebar wiring Props drill down Components read store (or thin props from store)
Re-render trigger setState Observable change + observer
Fetch vehicles useEffect — still external; not MobX’s job on day one

Install

npm install mobx mobx-react-lite

Store sketch

stores/vehicleResultsStore.ts — one class, one source of truth for filters + sort. Vehicles array fills in after fetch. 

import { makeAutoObservable } from "mobx";
import type { Vehicle } from "@/components/VehicleCard";

export class VehicleResultsStore {
  vehicles: Vehicle[] = [];
  isLoading = true;
  freeCancel = false;
  selectedServices: string[] = [];
  // … car class, car type, luggage, sortBy

  constructor() {
    makeAutoObservable(this);
  }

  get visibleVehicles() {
    return this.vehicles
      .filter(/* same rules as lesson 0009 */)
      .sort(/* same sort */);
  }

  setFreeCancel(next: boolean) {
    this.freeCancel = next;
  }

  clearFilters() {
  }

  setVehicles(data: Vehicle[]) {
    this.vehicles = data;
    this.isLoading = false;
  }
}
visibleVehicles is a computed — MobX caches it and recomputes when observables it read change. Same idea as deriving visible during render, but owned by the store. Docs: Computed values.

Page + observer

"use client";

import { useEffect, useState } from "react";
import { observer } from "mobx-react-lite";
import { VehicleResultsStore } from "@/stores/vehicleResultsStore";
import { fetchVehicles } from "@/lib/fetchVehicles";

const RidesMobXPage = observer(function RidesMobXPage() {
  const [store] = useState(() => new VehicleResultsStore());

  useEffect(() => {
    let cancelled = false;
    fetchVehicles().then((data) => {
      if (!cancelled) store.setVehicles(data);
    });
    return () => { cancelled = true; };
  }, [store]);

  // JSX reads store.isLoading, store.visibleVehicles, store.setFreeCancel, …
});

export default RidesMobXPage;

observer wraps a component so it re-renders when MobX observables used during render change. React integration.

Build order (recommended)

  1. Copy filter/sort rules from lift page into store computed — test mentally against one vehicle.
  2. Wire /rides/page.tsx to read store.visibleVehicles.
  3. Simple wiring first: pass store.freeCancel and store.setFreeCancel as props (store-backed controlled components).
  4. Then idiomatic: wrap FiltersPanel in observer and read store inside (less prop drilling).

Work repo tie-in

Compare your store to sdk/src/stores/api/transport-filter.store.ts and hooks/useStateOfFilters.ts — same shape: observable filter knobs, computed or derived results list, UI that subscribes.
