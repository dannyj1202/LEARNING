Lesson 0004 · React foundations

Type the Vehicle model

A typo in a prop name shouldn't wait until the page is open in a browser to be discovered. TypeScript catches it while you're still typing.

Mission tie-in: in Lesson 0003 the vehicles array was plain JavaScript — nothing stopped you from writing proce instead of price, or passing a string where a number belonged. Today that array gets a real shape, and mistakes against that shape become errors you see immediately, not bugs you find later.

A type is a shape you can check against

Official docs: object types describe the shape of an object — which properties exist and what type each one is. Define the shape once, then every value claimed to be that shape gets checked against it. 

type Vehicle = {
  id: string;
  title: string;
  price: number;
};

const vehicles: Vehicle[] = [
  { id: "v1", title: "Standard Sedan", price: 39 },
  { id: "v2", title: "Luxury Sedan", price: 168 },
];

Vehicle[] means "an array of things shaped like Vehicle." If any object in that array is missing a field, has an extra one, or has the wrong type for a field, TypeScript flags it — in your editor, before the code ever runs.

Rule to remember. This checking happens at edit/compile time, reading your code — not at run time, executing it. TypeScript never watches your program run; it reads the shapes and flags mismatches before a single line executes. That's a different bug-catching moment than anything JavaScript itself can do.

The same shape types the component's props

Reuse Vehicle to type what VehicleCard is allowed to receive — the same way Everyday Types annotates a function's parameters: 

function VehicleCard({ title, price }: Vehicle) {
  return (
    <article>
      <h2>{title}</h2>
      <p>USD {price}</p>
    </article>
  );
}

Now <VehicleCard title="SUV" price="89" /> — price as a string — is a red squiggle in your editor, not a bug someone notices in the rendered page three weeks from now.
