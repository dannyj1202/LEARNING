Lifting state up — filters actually filter

Your sidebar already has local useState. The list cannot see it. To make Free Cancellation / chips / luggage change which cards show, that state must live in the common parent and flow down as props. The visible list is then derived — computed from full data + filter state — not stored as a second copy.

Mission tie-in: side-project task 0008 (dashboard “Lifting state up”). File number is 0009 because lesson 0008 already taught local useState. This is the pivotal React move — the same idea the Rides filter store solves at work, first without MobX.

The one idea

When two children must stay in sync, lift the shared state to their closest common parent. Remove it from the children, hold it in the parent, pass the value and the setters (or handlers) down as props. Official docs: Sharing State Between Components. 
// BEFORE — list cannot see this
function FilterToggle() {
  const [on, setOn] = useState(false); // trapped here
}

// AFTER — page owns it; both sides receive props
function Home() {
  const [freeCancel, setFreeCancel] = useState(false);
  const visible = vehicles.filter(/* use freeCancel, chips, luggage, sort */);

  return (
    <>
      <FiltersPanel
        freeCancel={freeCancel}
        onFreeCancelChange={setFreeCancel}
        /* …other filter props */
      />
      {visible.map((v) => <VehicleCard key={v.id} {…v} />)}
    </>
  );
}

Three steps (same as the docs)

  1. Remove local useState from FilterToggle / chips / stepper (they become controlled).
  2. Pass the current value as a prop (on={freeCancel}).
  3. Pass a handler so the child can ask the parent to update (onChange={setFreeCancel} or onToggle={() => setFreeCancel(!freeCancel)}).

Derived, not stored

Keep the full vehicles array as the source of truth. Do not also keep a visibleVehicles state that you update in event handlers. On each render: 

const visible = vehicles
  .filter((v) => /* matches current filters */)
  .sort(/* by current sort */);

Filter state changes → React re-renders → visible is recalculated. One source of truth for the data; filters are just knobs.

Controlled vs uncontrolled (quick)

A chip group with its own useState is uncontrolled from the page’s point of view. Once selected and onSelectedChange come from props, it is controlled — the parent decides. Same vocabulary as form inputs.
