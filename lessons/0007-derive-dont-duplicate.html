Lesson 0007 · TypeScript depth

Derive, don't duplicate

You can already read the types in this repo. Depth is a different skill: writing a type without slowing down. The shortcut is that most types here aren't written from scratch at all — they're derived from a type that already exists. Four helpers cover nearly every case.

Mission tie-in: the card's goal is "typing doesn't slow you down." The thing that slows people down is hand-writing a near-duplicate of a type that's already there, then keeping the copy in sync forever. Every pattern below exists to avoid that — and each one is measured from your actual repo, not from the docs.

The one idea

If you're copy-pasting a type and changing a field or two, stop and derive it instead. A derived type stays linked to its source: when the base type gains a field, your derived type gains it for free. A copy silently drifts, and nothing tells you. (Field Guide §3.7 — "Reach for these utility types before hand-writing a near-duplicate interface.")

1. Partial<T> — everything optional

7 of the 8 API stores in packages/sdk/src/stores/api/ open with the identical three lines. It's the strongest convention in the SDK: 

type InitialState = Partial<{
  data: RawGetAirportSearchResponse;
  API_STATE: APIState;
}>;

A store gets constructed with whatever the caller happens to know — usually nothing ({}). Partial says "all of these fields, all optional" in one word, and still checks the type of any field that is supplied. Writing two ?s by hand would work; it just stops working the moment a third field appears.

2. Omit<T, K> and Pick<T, K> — a subset

Omit is everything except the named keys; Pick is only the named keys. The repo uses Omit to build its UI* type family — the API shape, re-expressed for display: 

// the API's shape
export interface DiscountType {
  type: string;
  value: number;      // ← a number, from the API
}

// the display shape: same thing, but value is already formatted
export interface UIDiscountType extends Omit<DiscountType, 'value'> {
  value: string | number;
}

Read that as "everything DiscountType has except value, plus my own value." Same trick, one level up, at transport-search.types.ts:118: UITransportVehicleResult extends Omit<TransportVehicleResult, 'priceDetail'> swaps a single nested field and inherits the other dozen untouched.

This is the App-types vs SDK-types boundary the card mentions, made concrete. Domain types (what the API returns) live in the SDK. UI* types are the same data after formatting — prices become strings, a hasDiscount flag gets added. Deriving rather than copying is what keeps the two provably in step.

3. Record<K, V> — a lookup table

Record<string, string> means "an object with string keys, whose values are all strings." 26 uses across the SDK. What's worth noticing is the value type they chose:

SpellingUses in the repoVerdict
Record<string, unknown> 14 Safe. You must narrow before touching a value.
Record<string, string> 10 Safe and specific — best when it's true.
Record<string, any> 2 A hole in the net. Fair review comment.

any switches off checking entirely — you can call anything on it and TypeScript won't blink. unknown forces you to check first. The Field Guide calls this "the most important distinction in the language" (§2.4), and your repo lands on the right side of it 24 times out of 26.

4. The pattern that isn't in the cheatsheet

This is the repo-specific one, and the reason the card asks you to write an addendum. From TypedSearchInputField.tsx — the whole file: 

type CellProps = Parameters<typeof Cell>[0];

export type Props = Omit<CellProps, 'primaryText'> & {
  primaryText?: ReactNode;
};

export default function TypedSearchInputField({ primaryText, ...rest }: Props): JSX.Element {
  return <Cell {...rest} primaryText={primaryText as CellProps['primaryText']} />;
}

Three separate moves, worth naming individually:

  • Parameters<typeof Cell>[0] — grab a component's props type from the component itself, when the library doesn't export it. Parameters<…> gives the argument list as a tuple; [0] takes the first.
  • Omit<…> & { … } — subtract the field you need to change, then intersect (& = "and also") your own version back on. This is how you override one field of a type you don't control.
  • primaryText as CellProps['primaryText'] — an assertion, confined to one line. T['key'] is an indexed access type: "whatever type CellProps gives that key."

Read the file's own comment for the reasoning: "Rather than scattering @ts-ignore at every call site, this wrapper accepts a typed primaryText: ReactNode and applies the assertion to the DS type exactly once, here." That is the good use of an escape hatch — one place, documented, with a wrapper around it. Worth stealing.
