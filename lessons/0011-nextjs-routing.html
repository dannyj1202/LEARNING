Lesson 0011 · Next.js App Router

Routing — folders are URLs

Your vehicle page works, but it all lives at /. Real apps have multiple screens. In the App Router, the app/ folder is the route table — no separate router config file. You extract shared UI into components, put each screen on its own route, and link between them with Link.

Mission tie-in: side-project task 0010 (dashboard “Next.js routing”). File number is 0011 because lesson 0010 is useEffect. End-of-week-2 checkpoint: demo filters on a real route, not only the home page.

The one idea

Folder path under app/ = URL path. A page.tsx in that folder makes the segment public. Official docs: Layouts and Pages.
File URL Role
app/page.tsx / Landing — links to other routes
app/rides-lift/page.tsx /rides-lift Your lift-state vehicle page (08a)
app/rides/page.tsx /rides MobX store version — lesson 0012
app/layout.tsx wraps all routes Shared shell: <html>, fonts, metadata

Build steps (side project)

  1. Extract — move the big Home component from app/page.tsx into components/RidesResultsPage.tsx (keep "use client" there — hooks and Emotion need it).
  2. Lift route — create app/rides-lift/page.tsx that renders <RidesResultsPage /> (thin file, ~3 lines).
  3. Landing — replace app/page.tsx with a simple home page and Link components to /rides-lift and /rides.
  4. Test — npm run dev, click each link, confirm URL bar and page content match. 
// app/rides-lift/page.tsx — folder name = URL segment
import RidesResultsPage from "@/components/RidesResultsPage";

export default function RidesLiftPage() {
  return <RidesResultsPage />;
}
// app/page.tsx — no "use client" needed (no hooks)
import Link from "next/link";

export default function Home() {
  return (
    <main>
      <h1>Almosafer learning</h1>
      <Link href="/rides-lift">Lift state version</Link>
      <Link href="/rides">MobX store version</Link>
    </main>
  );
}

layout.tsx vs page.tsx

  • layout — wraps child routes; stays mounted when you navigate between pages in the same layout (good for nav bars you add later).
  • page — the actual screen for that URL segment; swaps when the route changes.

Your project already has app/layout.tsx with fonts and metadata. You usually leave it alone while adding routes underneath.

Server vs Client (just enough for now)

App Router pages are Server Components by default — no hooks, no browser-only APIs. Your vehicle page uses useState, useEffect, and Emotion, so it stays a Client Component ("use client" at the top of the file that uses hooks).

Pattern: thin page.tsx (can be server) imports a "use client" component that owns the interactive UI.

Link vs <a>

Use next/link for in-app navigation — client-side transition without full reload. Plain <a href> still works but reloads the whole page.

Work repo tie-in

In ct-web-transport, routes live under the app package’s pages/containers split — different folder convention, same idea: URL maps to a screen component. After this lesson you should recognize “this file is the page for this path.”
