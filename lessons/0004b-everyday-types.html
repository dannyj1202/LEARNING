Everyday types

Vehicle used string and number without a second thought. This lesson is about the other everyday shapes — tuples and function types — that show up constantly once you're reading real code instead of writing it from scratch.

Mission tie-in: in Lesson 0004 you typed Vehicle and caught a typo'd prop before it ran. Two more everyday shapes are coming up fast: useState (lesson 0007) returns a tuple, and a sort function you'll write for the results list is a function type — worth knowing both before you meet them in the wild.

Most types, you never write

TypeScript infers types automatically from the value on the right-hand side. You only annotate when the type isn't obvious from context — most often, function parameters. 

let age = 36;              // inferred as number, no annotation needed
const vehicles = [39, 168]; // inferred as number[]

function calculateTotal(price: number, quantity: number) {
  return price * quantity;  // return type inferred as number
}

Source: TypeScript Field Guide, §1.3 — "In practice you'll rarely write let age: number = 36. TypeScript infers the type automatically."

Arrays vs. tuples — when position means something

An array (Vehicle[]) is a list of same-shaped things, any length. A tuple is a fixed-length array where each position has its own specific type — TypeScript enforces both the length and what goes where. 

// Array: any number of same-shaped items
const prices: number[] = [39, 168, 89];

// Tuple: exactly two items, and position 0 must be a number,
// position 1 must be a string
type PriceEntry = [number, string];
const entry: PriceEntry = [39, "Standard Sedan"];
Why this matters soon. useState(0) (lesson 0007) doesn't return an object — it returns a tuple: [value, setValue]. Position 0 is always the current value, position 1 is always the setter function. That's not a convention you memorize; it's a tuple type doing its job.

Function types — a signature you can hand around

A function's type is its parameter types plus its return type. You can name that signature and use it as a type, the same way Vehicle names an object shape. 

type SortFn = (a: Vehicle, b: Vehicle) => number;

const byPriceAscending: SortFn = (a, b) => a.price - b.price;

Anything typed SortFn is guaranteed to take two vehicles and return a number — the exact shape the results list's sort dropdown will need later.
