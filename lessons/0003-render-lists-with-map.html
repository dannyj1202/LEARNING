Render a list with .map()

Six vehicles on the page, but you should never type <VehicleCard /> six times. Drive it from an array instead.

Mission tie-in: in Lesson 0002 you configured one VehicleCard by hand-writing its props twice. Today the vehicles live in a plain JS array — the shape mock data will actually arrive in — and the six cards come from that array, not from six lines you wrote yourself.

The problem with writing it by hand

This works, but it doesn't scale — and it can't respond to real data: 

<VehicleCard title="Standard Sedan" price={39} />
<VehicleCard title="Luxury Sedan" price={168} />
<VehicleCard title="SUV" price={89} />
<VehicleCard title="Minivan" price={74} />
<VehicleCard title="Pickup" price={95} />
<VehicleCard title="Compact" price={45} />

If the vehicle list came back from an API tomorrow with eight vehicles instead of six, this code wouldn't change to match it. You need the JSX to come from the data.

Array in, elements out

Official React docs: use JavaScript's array .map() to turn an array of data into an array of components. .map() isn't a React feature — it's plain JavaScript that runs a function over every item and collects the results into a new array. React is happy rendering an array of JSX elements exactly like it renders one. 

const vehicles = [
  { id: "v1", title: "Standard Sedan", price: 39 },
  { id: "v2", title: "Luxury Sedan", price: 168 },
  { id: "v3", title: "SUV", price: 89 },
];

function ResultsList() {
  return (
    <div>
      {vehicles.map((vehicle) => (
        <VehicleCard
          key={vehicle.id}
          title={vehicle.title}
          price={vehicle.price}
        />
      ))}
    </div>
  );
}

Add a vehicle to the vehicles array and a new card appears. Nothing about ResultsList or VehicleCard changes — exactly the scaling problem above, solved.

Why key is not optional

Each element in the array needs a key — a value stable and unique among its siblings. React uses it to tell items apart across re-renders: which one moved, which one was removed, which one is new. Without it, React can only guess by position, and guessing by position breaks the moment the list is filtered, sorted, or reordered.

Rule to remember. Prefer a stable id from the data (vehicle.id) over the array index. An index looks fine today, but you're about to build filtering and sorting in this exact list (lesson 08a) — the moment sorting reorders the array, index-as-key silently mismatches cards to the wrong data.
