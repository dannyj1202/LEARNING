Lesson 0001 · React foundations

See the vehicle page as components

Before Next.js, TypeScript, or Emotion: learn to carve your booking UI into reusable pieces. That carving skill is what React is built around.

Mission tie-in: you will build this results page. Today you only learn to name the pieces — the same pieces you will later implement as React components.

What a component is

Official React docs: a component is a piece of the UI with its own logic and appearance — as small as a button, or as large as a page. In code, it is a JavaScript function whose name starts with a capital letter and that returns markup (JSX). 

function BookNowButton() {
  return <button type="button">Book now</button>;
}

You then nest components the way you nest HTML tags (react.dev/learn): 

function VehicleCard() {
  return (
    <article>
      <h2>Standard Sedan</h2>
      <BookNowButton />
    </article>
  );
}
Rule to remember. Lowercase names are treated as HTML tags (button). Capitalised names are your components (BookNowButton). That capital letter is not style — React depends on it.

Your target, cut into pieces

A useful first split for this page (cheat sheet: vehicle page component map):

ResultsPage — owns the whole view
SearchSummary — route, date, passengers
FiltersPanel — left column
FilterToggle — Free Cancellation
FilterChip — Meet & Greet, Luxury, SUV…
PriceRange — min/max slider
LuggageStepper — − / count / +
ResultsList — sort + cards
SortSelect — Lowest price
VehicleCard — image, title, capacity, features, price, Book now

Notice VehicleCard appears six times in the screenshot with different data. That repetition is the signal: one component, many instances. Filters reuse FilterChip the same way.
